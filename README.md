# 🚀 NoVate MCP

**Собственный MCP-сервер на твоём VPS + веб-панель управления проектами.**
Подключай любой MCP-клиент (ИИ-агента) — он получит инструменты
для выполнения команд и работы с файлами на сервере.

## ✨ Возможности

- 🤖 **11 инструментов для MCP-клиента** — файлы (`read_file`, `write_file`, `list_files`, `search_in_files`, `delete_file`, `move_file`), `run_command`, фоновые задачи (`run_background` + `poll_task`), `server_stats`, `make_backup`
- 📊 **Панель «NoVate MCP»** — статистика сервера, проекты, просмотр файлов и скачивание проектов архивом
- 🔑 **Вход в панель через Telegram (OpenID Connect)** — без паролей и токенов: доступ по списку Telegram ID
- 🗄 **Бэкапы в Telegram** — по расписанию или кнопкой, загрузка локальных бэкапов с проверкой, шифрование AES-256, восстановление в один клик
- 🔔 **Telegram-алерты** — входы в панель, отклонённые попытки, смена настроек, сбои бэкапов
- 🎨 **Современный минималистичный UI на TypeScript (Bun)** — CSS-анимации, тост-уведомления, акцент `#1ED895`, минимальная нагрузка на систему
- ⚙️ **Настройки из панели** — редактирование текущих значений, генерация локальных секретов и возврат к `.env`
- 🔐 **Безопасность по кругу** — Bearer-токен для MCP, OIDC + HMAC-сессии для панели, изоляция папки, контейнеры не от root
- 🌍 **Публичные сайты** — всё, что агент создаст в проекте, сразу открывается по ссылке
- 🔄 **CI/CD из коробки** — пуш в `main` → GitHub Actions → GHCR → `docker compose pull` на сервере

## 🏗 Архитектура

```
MCP-клиент ──HTTPS + Bearer──┐
                             ▼
                     ДОМЕН (Caddy, авто-HTTPS)
                             │
             ┌───────────────┼─────────────────┐
             ▼               ▼                 ▼
          /mcp/          /projects/            /
             │               │                 │
             ▼               ▼                 ▼
       mcp:8000      статика проектов   dashboard:8001
       (FastMCP,     (публичный          (панель на Bun + TS,
        4 инстр.)     просмотр сайтов)    вход через Telegram OIDC)
                             │
                             ▼
                   ./projects на сервере —
                   единственная папка, доступная MCP

       backup (фоновый сервис): tar.gz проектов и настроек панели ->
       ./backups (последние BACKUP_KEEP копий) + отправка в Telegram
```

GitHub Actions собирает **три образа** из одного Dockerfile (multi-stage)
в один GHCR-пакет с тегами `mcp-latest`, `dashboard-latest` и `backup-latest`.

## 🚀 Быстрый старт

### Шаг 1. Подготовь репозиторий (один раз)

1. Запушь все файлы, включая `.github/workflows/build.yml`.
2. Вкладка **Actions** → дождись зелёной галочки ✅ (все три образа собраны).
3. **Сделай пакет публичным** (GHCR-пакеты по умолчанию приватные!):
   GitHub → Packages → `novate-mcp` → Package settings → Change visibility → **Public**.
   Один пакет, три тега — менять видимость нужно один раз.

### Шаг 2. Telegram: бот + OIDC-приложение (один раз)

Одного и того же бота достаточно и для входа в панель, и для бэкапов.

1. В **@BotFather** создай бота (или возьми существующего) — его **токен**
   пригодится для бэкапов (`TG_BOT_TOKEN`).
2. Настройки OIDC живут в **мини-приложении BotFather** (кнопка «Open» в чате
   с BotFather, не текстовые команды): выбери бота → **Bot Settings → Web Login**.
   Там показаны **Client ID** и **Client Secret** (`TG_CLIENT_ID` / `TG_CLIENT_SECRET`)
   — бери их именно оттуда; Client Secret — это НЕ токен бота.
3. В разделе Web Login добавь в **Allowed URLs** оба адреса:
   `https://ДОМЕН` и `https://ДОМЕН/auth/callback`.
4. Нажми Start в диалоге с ботом — иначе он не сможет прислать тебе бэкап в личку.
5. Узнай свой Telegram ID у **@userinfobot** — впишешь его в `ALLOWED_TG_USERS`.

### Шаг 3. Сервер (Ubuntu 24.04)

Нужны: VPS, домен с A-записью на IP сервера, доступ по SSH.

```bash
# Загрузи install.sh на сервер, затем:
bash install.sh
```

Скрипт сам: обновит систему → поставит Docker → настроит UFW →
скачает инфра-файлы из репозитория → сгенерирует токены →
сделает `docker compose pull` → запустит всё.

### Шаг 4. Заполни .env

```bash
nano ~/mcp-server/.env
# TG_CLIENT_ID, TG_CLIENT_SECRET — из шага 2
# ALLOWED_TG_USERS — Telegram ID через запятую (кому разрешён вход в панель)
# TG_BOT_TOKEN, TG_CHAT_ID — бот и чат для бэкапов
cd ~/mcp-server && docker compose up -d
```

### Шаг 5. Проверка

```bash
curl -i https://ДОМЕН/mcp/      # ожидается: 401 Unauthorized
```

- `https://ДОМЕН/` — страница входа панели с кнопкой «Войти через Telegram»
- `https://ДОМЕН/projects/` — публичный просмотр проектов

### Шаг 6. Подключение MCP-клиента

Подойдёт любой клиент с поддержкой MCP по HTTP и Bearer-авторизации:

| Параметр | Значение |
|---|---|
| URL | `https://ДОМЕН/mcp/` |
| Аутентификация | Bearer Token |
| Токен | `MCP_TOKEN` из `~/mcp-server/.env` |

## 📊 Панель управления

Вход — только через Telegram (OpenID Connect): нажми «Войти через Telegram»,
подтверди вход в приложении Telegram — готово. Подписанная HMAC-cookie
живёт 7 дней. Доступ есть только у Telegram ID из `ALLOWED_TG_USERS`,
а ID отклонённых попыток входа видны в логах: `docker compose logs dashboard`.

- **Проекты** — карточки с размером, числом файлов и датой изменения.
  «Открыть сайт» показывается только при наличии `index.html` в корне проекта;
  «Скачать» потоково формирует tar.gz прямо в HTTP-ответе, поэтому браузер
  начинает загрузку сразу даже для больших проектов, а временный файл не создаётся.
- **Файлы** — навигация по папкам, скачивание любого файла, дата изменения
  для каждого файла и каталога.
- **Бэкапы** — статус последнего бэкапа, локальные архивы со скачиванием,
  кнопки «Сделать бэкап сейчас» и «Загрузить бэкап». Загружаемый файл
  проверяется по имени, tar.gz/AES-256 формату, структуре `projects/`,
  небезопасным путям, ссылкам и специальным файлам.
- **Статистика** — проектов/файлов (с анимированными счётчиками),
  занято и свободно на диске, аптайм сервера.
- **Настройки** — переопределение значений из `.env` (см. ниже).
- **Поиск и фильтры** — мгновенный поиск по названиям проектов, файлов и папок;
  фильтрация по типу и периоду изменения; сортировка по названию, дате, размеру
  и числу файлов без перезагрузки страницы.
- **Уведомления** — единая тост-система в правом верхнем углу с автозакрытием.

Технически: сервер на **Bun** без фреймворков (минимум памяти и CPU),
клиентский JS — один минифицированный файл (~1 КБ), вся анимация на CSS
(transform/opacity — работает на GPU), уважает `prefers-reduced-motion`.
Панель монтирует проекты в режиме **только чтение**: изменять файлы
может только MCP.

## 🗄 Бэкапы

Фоновый контейнер `backup` раз в `BACKUP_INTERVAL_HOURS` часов
(по умолчанию 24) собирает tar.gz-архив: все проекты + настройки панели.

- Архив складывается в `~/mcp-server/backups/` (хранятся последние
  `BACKUP_KEEP` копий, старые удаляются автоматически).
- Каждый архив отправляется ботом `TG_BOT_TOKEN` в чат `TG_CHAT_ID`
  (личный чат — если указать свой Telegram ID).
- Кнопка **«Сделать бэкап сейчас»** — в панели, раздел «Бэкапы», или инструмент
  `make_backup` из MCP-клиента.
- **Загрузка локального бэкапа**: панель принимает только файлы вида
  `novate-backup-YYYYMMDD-HHMMSS.tar.gz[.enc]` до 512 МБ. Перед сохранением
  проверяются формат, структура NoVate MCP и безопасность содержимого.
  Для проверки `.enc` нужен текущий `BACKUP_PASSWORD`.
- **Восстановление в один клик**: «Восстановить» у любого архива перезаписывает
  проекты из него (перед этим автоматически делается страховочный бэкап;
  настройки панели из архива не восстанавливаются).
- **Шифрование**: если задан `BACKUP_PASSWORD`, архивы шифруются AES-256
  (файлы `.enc`) и в Telegram, и локально. Расшифровка скачанного:
  `openssl enc -d -aes-256-cbc -pbkdf2 -in файл.enc -out файл.tar.gz`.
- Telegram не настроен (нет токена/чата) — бэкапы остаются локальными.
- Архив больше 50 МБ (лимит Bot API) — бот пришлёт уведомление,
  а архив можно скачать в панели или забрать из папки `backups/`.
- Все настройки бэкапов можно менять прямо в панели —
  применяются в течение минуты, без перезапуска.
- Логи сервиса: `docker compose logs -f backup`.

## ⚙️ Настройки

Все значения живут в `.env` на сервере (не коммитится!).
Приоритет: **переопределение в панели** > **`.env`** (значения по умолчанию).

| Ключ | Назначение | Смена из панели |
|---|---|---|
| `MCP_TOKEN` | Bearer-токен для MCP-клиента | ✅ генерация и копирование; MCP-процесс применяет автоматически |
| `SESSION_SECRET` | Секрет подписи сессий панели (HMAC) | ✅ генерация и копирование; сразу завершает текущие сессии |
| `TG_CLIENT_ID` | Client ID OIDC-приложения Telegram | ✅ сразу |
| `TG_CLIENT_SECRET` | Client Secret OIDC-приложения | ✅ ручная замена (значение выдаёт Telegram) |
| `ALLOWED_TG_USERS` | Telegram ID с доступом в панель, через запятую | ✅ поле с текущим списком: добавление, изменение и удаление |
| `TG_BOT_TOKEN` | Токен бота, присылающего бэкапы | ✅ ручная замена (значение выдаёт Telegram) |
| `TG_CHAT_ID` | ID чата для бэкапов | ✅ редактирование или очистка, в течение минуты |
| `BACKUP_INTERVAL_HOURS` | Интервал бэкапов, часов | ✅ в течение минуты |
| `BACKUP_KEEP` | Сколько архивов хранить локально | ✅ в течение минуты |
| `BACKUP_PASSWORD` | Пароль шифрования архивов (AES-256) | ✅ генерация и копирование, в течение минуты |
| `DOMAIN` | Домен сервера | ✅ для ссылок и callback Telegram; HTTPS-домен Caddy — только через `.env` + install.sh |
| `TZ` | Часовой пояс контейнеров (время в панели, логи, бэкапы) | 👉 только `.env`, затем `docker compose up -d` |

Обычные значения отображаются непосредственно в полях — их можно дополнять,
исправлять и очищать. Локальные секреты (`MCP_TOKEN`, `SESSION_SECRET`,
`BACKUP_PASSWORD`) генерируются панелью и показываются один раз для копирования.
`TG_CLIENT_SECRET` и `TG_BOT_TOKEN` выдаются Telegram и заменяются вручную.
Кнопка **«По умолчанию»** удаляет переопределение — снова действует `.env`.
`PROJECTS_DIR` в панели не показывается, потому что это Docker-монтирование.
Для автоматического применения `MCP_TOKEN` контейнеру dashboard не выдаётся
опасный доступ к Docker socket: MCP-процесс сам отслеживает изменение и делает re-exec.

## 🔐 Безопасность

- MCP отвергает запросы без токена (проверка: `curl` выше отдаёт 401).
- Вход в панель — Telegram OpenID Connect: PKCE (S256), одноразовый `state`
  в короткоживущей подписанной cookie, подпись `id_token` проверяется по
  публичным ключам Telegram (JWKS), проверяются `iss`, `aud` и `exp`.
- Доступ к панели — только у Telegram ID из `ALLOWED_TG_USERS`; список
  проверяется при каждом запросе, поэтому убранный из списка пользователь
  теряет доступ мгновенно.
- Сессия панели — HMAC-подписанная cookie (ключ `SESSION_SECRET`),
  HttpOnly + Secure + SameSite=Lax, живёт 7 дней.
- Подписи сравниваются через sha256 + timingSafeEqual (без утечки длины).
- Все файловые операции ограничены папкой проектов — защита от `../` в коде
  + Docker-монтирование только этой папки.
- `run_command` выполняется **внутри контейнера**, а не на хосте.
- Контейнеры работают не от root (uid 1000).
- Восстановление из бэкапа запускается только из авторизованной панели;
  перед восстановлением автоматически делается страховочный бэкап.
- Наружу открыты только 80/443 (UFW + Caddy); порты 8000/8001 внутренние,
  сервис бэкапов наружу не торчит вовсе.
- Бэкапы содержат `overrides.json` (там могут быть переопределённые секреты) —
  береги чат с бэкапами и папку `backups/` как секреты.
- Всё в `projects/` публично по ссылкам `/projects/...` — это нужно для
  просмотра созданных сайтов. Панель при этом доступна только после входа.

## 🔄 Обновление

```bash
# 1. Запушил изменения в main -> Actions собрал новые образы

cd ~/mcp-server
docker compose pull
docker compose up -d
```

## 🛠 Полезные команды

```bash
cd ~/mcp-server
docker compose ps                    # статус контейнеров
docker compose logs -f mcp           # логи MCP-сервера
docker compose logs -f dashboard     # логи панели (тут ID отклонённых входов)
docker compose logs -f backup        # логи бэкапов
docker compose restart               # перезапуск
docker compose down                  # остановить всё
```
